# 複数プラン対応 テスト仕様書

作成日: 2026-08-18
対象: dx-invoice（玉泉院向け葬儀業務管理システム）
関連資料: [PLAN_FEATURE_SPEC.md](./PLAN_FEATURE_SPEC.md)（追加変更仕様書、先にこちらをお読みください）

## 0. テスト前提条件

- テスト環境（ローカル or 検証環境）で、管理者権限（`isAdmin: true`）のユーザーでログインできること
- 初期プランとして「基本プラン」「家族葬27万円コース」「家族葬37万円コース」の3件が登録済みであること（`/plans` 画面で確認）
- テスト用の顧客（案件）データが1件以上存在すること
- 商品マスタに、セット親商品（例：式場祭壇など、親祭壇バッジが付いている商品）とその子商品（セット子・`isDefaultSet` なバリアントを持つもの）が最低1組登録されていること（プラン切替の再計算テストに使用）

以下、テスト観点は大分類ごとに A〜G で番号を振る。各テストは独立して実施できるが、C・D・E は連続したシナリオになっている箇所がある。

| No | 項目 | 手順 | 期待結果 |

| A-2 | 画面アクセス制御 | 管理者以外のアカウントで `/plans` にアクセスする | アクセスできない（商品管理・店舗管理と同様の管理者限定制御が効いている） |

| A-4 | プラン名変更 | 任意のプランタブの鉛筆アイコン → 名前を変更 → チェックマークで確定 | タブの表示名が更新され、再読み込み後も保持されている |

## B. プラン別商品設定

商品ごとに設定できるのは「表示する/しない」「セット可否（初期セット品の0円扱いの適用範囲）」「デフォルトセット品（一般商品専用）」の3点。

- **セット可否**セレクト（デフォルトのまま／不可／会員のみ／一般のみ／両方、商品編集画面の同名設定と同じ選択肢）は、**セット親商品（一覧に「セット親商品」バッジが付いているもの）にのみ無効化**される。一般商品・セット子商品では常に操作可能。
- **デフォルトセット品**セレクト（その商品のバリアント一覧＋「なし」）は**一般商品（親でも子でもない商品）にのみ表示**される。セット親・セット子商品の行では「—」表示になり、このセレクト自体が出てこない（セット子商品は商品マスタ側で既に初期セット品が設定済みのため対象外）。

| No | 項目 | 手順 | 期待結果 |
|---|---|---|---|
| B-1 | プラン切替で一覧が変わる | 「基本プラン」タブと「家族葬27万円コース」タブを行き来する | 表示される商品一覧の設定値（表示チェック・セット可否・デフォルトセット品）がタブごとに独立して保持されている |
| B-2 | 初期状態の確認 | 新規登録したプラン（A-3で作成したもの）のタブを開く | 全商品が「表示する」チェックON、「セット可否」が「デフォルトのまま」、一般商品の「デフォルトセット品」が「なし」になっている（商品マスタと差分が無い状態） |
| B-3 | 商品の非表示化 | 「家族葬27万円コース」で任意の商品の「表示する」チェックを外す → 「変更を保存」 | 保存後、再読み込みしてもチェックが外れた状態が保持されている |
| B-4 | セット子商品ではセット可否が変更できる | 一覧に「セット子商品」バッジが付いている商品の「セット可否」を「不可」に変更 → 保存 | セレクトが操作可能。保存後、再読み込みしても「不可」が保持されている |
| B-4' | セット親商品はセット可否が変更不可 | 「セット親商品」バッジが付いている商品の「セット可否」セレクトを確認する | セレクトがグレーアウトして操作できない（デフォルトのまま固定） |
| B-5 | セット可否をデフォルトへ戻す | B-4で変更した商品の「セット可否」を再度「デフォルトのまま」に戻す → 保存 | 保存後、再読み込みで「デフォルトのまま」の状態（商品マスタ本来の設定に戻る）を維持している |
| B-6 | 一般商品でデフォルトセット品を選択 | 一般商品（複数バリアントを持つもの）の「デフォルトセット品」セレクトから任意のバリアントを選択 → セット可否も「両方」等に設定 → 保存 | 保存後、再読み込みしても選択したバリアントとセット可否が保持されている |
| B-6' | セット親・セット子商品にはデフォルトセット品セレクトが無い | セット親商品・セット子商品の行の「デフォルトセット品」列を確認する | セレクトではなく「—」が表示されており、選択操作自体ができない |
| B-7 | デフォルトセット品をデフォルトへ戻す | B-6で選択したバリアントを再度「なし（デフォルトのまま）」に戻す → 保存 | 保存後、商品マスタ本来の状態（`isDefaultSet`未設定）に戻る |
| B-8 | 未保存件数の表示 | いくつかの項目を変更する | 「変更を保存（n件）」のようにボタンに変更件数が表示され、保存前は保存ボタンが有効化されている |
| B-9 | 他プランへの影響が無いこと | B-3〜B-7の変更後、「基本プラン」タブを開く | 基本プランの設定は一切変わっていない（表示チェック・セット可否・デフォルトセット品ともに元のまま） |
| B-10 | 一括保存前のキャンセル相当動作 | 変更後、保存せずに別のプランタブに切り替えて戻ってくる | 保存していない変更は破棄され、DB上の値（前回保存時点の値）が再表示される |

## C. 見積作成画面 — プラン選択の基本動作

| No | 項目 | 手順 | 期待結果 |
|---|---|---|---|
| C-1 | MODE切替ボタンの廃止確認 | 任意の案件で見積作成画面を開く | 従来あった「MODE」（一覧から登録／カード型で順番に選択）の切替ボタンが表示されておらず、常に一覧形式の明細テーブルのみが表示される |
| C-2 | 新規作成時のプラン初期値 | 新規見積作成画面を開く | プランのセレクトボックスが「基本プラン」になっている |
| C-3 | プラン選択肢の内容 | プランのセレクトボックスを開く | A-6で非表示化したプランが選択肢に出てこないこと（基本プラン・家族葬27万円コース・家族葬37万円コースなど有効なプランのみ表示） |
| C-4 | 商品の表示/非表示反映 | Bで「家族葬27万円コース」で非表示化した商品（B-3）を選び、見積作成画面でプランを「家族葬27万円コース」に変更する | その商品が明細の選択肢（一覧）に出てこない |
| C-5 | セット可否変更の金額反映 | B-4で「セット可否」を「不可」に変更したセット子商品について、対応する親商品と一緒に数量を入れ、プランを「基本プラン」→「家族葬27万円コース」に切り替える | 基本プランでは通常のセット0円判定（`isDefaultSet` かつ会員/一般の条件を満たせば0円）が働くのに対し、「不可」に変更したプランでは同じ商品が0円扱いにならず通常の金額が加算される。画面下部の合計にもその差分が反映される |
| C-5' | セット可否「両方」への変更確認 | B-4とは逆に、あるセット子商品のセット可否をプランで「両方」に変更し、一般顧客としてそのプランで見積を作る | 商品マスタ本来の設定では0円にならない条件（例：本来は会員のみ0円）でも、そのプランでは一般顧客でも0円扱いになる |
| C-6 | 一般商品のデフォルトセット品設定が金額に反映される | B-6で「デフォルトセット品」に特定のバリアントを指定し、セット可否を「両方」にした一般商品について、そのプランで見積を作成し、指定したバリアントを選んで数量を入れる | その一般商品が0円扱いになる（本来は一般商品なので通常は課金されるはずの商品が、そのプランに限り無料になる） |
| C-6' | デフォルトセット品で指定していないバリアントは対象外 | C-6と同じ商品で、指定したバリアント**以外**の種類を選んで数量を入れる | 0円にならず通常通り課金される（1商品につき指定した1バリアントのみが対象） |
| C-6'' | 他プランに影響しないこと | C-6で設定したプラン以外（例：基本プラン）で同じ一般商品を選ぶ | 通常通り課金され、0円にならない（商品マスタ自体は変更されていないため） |
| C-7 | 見積保存とプランの永続化 | プランを「家族葬27万円コース」にして明細を入力し「登録」 | 保存後、詳細画面を開き直してもプランが「家族葬27万円コース」のまま表示される |

## D. プラン切替時の確認ダイアログ・再計算

| No | 項目 | 手順 | 期待結果 |
|---|---|---|---|
| D-1 | 消える明細が無い場合 | 現在選択中プランに存在し、切替先プランにも存在する（表示される）商品だけで明細を組んだ見積で、プランを切り替える | 確認ダイアログが出ずに即座に切り替わる |
| D-2 | 消える明細がある場合の確認ダイアログ | 現在のプランでは表示されるが切替先プランでは非表示になる商品（B-3で設定した商品）に数量を入れた状態で、プランをその切替先に変更する | 該当商品名を含む確認ダイアログが表示される |
| D-3 | 確認ダイアログでキャンセル | D-2の状態でダイアログの「キャンセル」を選ぶ | プランの選択（セレクトボックスの表示）が元のプランのまま変わらず、明細もそのまま残っている |
| D-4 | 確認ダイアログでOK | D-2の状態でダイアログの「OK」を選ぶ | 該当明細が一覧から消え、数量・金額がクリアされる。画面下部の小計・消費税・合計・差引合計が再計算された値になっている |
| D-5 | 再計算後の保存 | D-4の後、「更新」（または「登録」）で保存する | 保存が正常に完了し、再度開いたときに削除された明細が復活していないこと |
| D-6 | 数量0の明細は確認対象外 | 切替先で非表示になる商品だが、数量が0（未選択）の状態でプランを切り替える | 確認ダイアログが出ずにそのまま切り替わる（数量が入っている明細のみが確認対象） |

|---|---|---|---|

## 不具合報告時のお願い

不具合を見つけた場合は、以下を含めて報告してください。

1. 該当するテストNo（例: D-2）
2. 使用したプラン名・商品名・見積ID（分かれば）
3. 期待結果と実際の結果の差分
4. ブラウザのコンソールエラー（開発者ツールの Console タブの内容、あれば）
